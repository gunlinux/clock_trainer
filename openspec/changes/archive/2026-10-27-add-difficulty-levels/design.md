# Design

## Context

См. `proposal.md` — зачем. Технический контекст, важный для решений:

- `app.js` — один IIFE в строгом режиме, весь стейт в модульной области: `state = { mode, answer, score, locked }`, плюс `dH`/`dM` для режима 3 и один общий `timer` через `schedule()`.
- Циферблат уже генерируется в `app.js` при старте: 60 штрихов в `#ticks` и 12 цифр в `#numbers` (`document.createElementNS`, радиус цифр 68, длина минутной стрелки 56, часовой 38).
- Ответы — это минуты от полуночи; `visualKey()` склеивает время, одинаковое на 12-часовом циферблате, и `buildOptions()` уже дедуплицирует по этому ключу.
- Длины стрелок и радиус цифр задают свободное место: подписи минут должны попасть в кольцо между концом минутной стрелки (r≈56) и цифрами часов (r=68).
- Нет сборки, тестов и зависимостей; проверка — ручная в браузере. Стиль ES5, никакого `localStorage`.

## Goals / Non-Goals

**Goals:**

- Три уровня сложности только для режима 1, переключаемые без перезагрузки.
- Подписи минут, которые включаются и выключаются вместе с уровнем, не ломая существующую геометрию SVG.
- Генерация вариантов и времени, зависящая от уровня, но повторно использующая существующие механизмы дедупликации.
- Пауза 5 секунд, не конфликтующая с общим таймером перехода к следующему заданию.
- Штрафы, которые видит ребёнок, без ухода счёта в минус.

**Non-Goals:**

- Не менять режимы «Запиши время» и «Поставь время» (включая точность их заданий и их задержки).
- Не добавлять сохранение уровня, счёта или статистики между перезагрузками.
- Не вводить адаптивную сложность, таймеры на задание и звуки.
- Не переписывать `app.js` на современный JS и не добавлять сборку/тесты.

## Decisions

### 1. Конфигурация уровней одной таблицей

```js
var LEVELS = {
  1: { step: 5, minutes: true,  penaltyEvery: 0 },
  2: { step: 5, minutes: false, penaltyEvery: 3 },
  3: { step: 1, minutes: false, penaltyEvery: 2 }
};
```

`state.level` (по умолчанию 1) и `state.mistakes` добавляются в существующий `state`. Все проверки читают `LEVELS[state.level]`, а не разбросанные `if (state.level === 3)`.

*Альтернатива:* отдельные флаги на каждый режим — быстрее разъедется при добавлении уровня 4.

### 2. Подписи минут рисуются один раз, видимость — классом

На старте рядом с цифрами часов в новую группу `#minuteLabels` генерируются 12 `<text>` со значениями 5…60 на радиусе ≈58 (между концом минутной стрелки и цифрами часов), с классом `min`. Видимость переключается классом `minutes-on` на `<svg id="clock">`:

```css
#clock .min { display:none; }
#clock.minutes-on .min { display:block; }
```

`setLevel()` только добавляет/снимает класс. Так смена уровня не пересоздаёт DOM и не мешает уже идущей CSS-анимации стрелок.

*Альтернатива:* удалять/создавать подписи при каждом переключении — лишняя работа и риск рассинхронизации с геометрией.

*Альтернатива:* подписи снаружи циферблата — не помещаются в `viewBox 0 0 200 200` (внешний радиус уже 92, плюс штрихи до 89).

### 3. Шаг времени — параметр генератора

`randomTime()` получает аргумент `step` (`randomTime(step)`): минуты выбираются из `0, step, 2·step, …`. Режимы 2 и 3 вызывают `randomTime(5)` как раньше, режим 1 — `randomTime(LEVELS[state.level].step)`. Часы по-прежнему 0–23, чтобы задание звучало в 24-часовом виде.

### 4. Варианты: общий пул + особый путь для уровня 3

`buildOptions(ans, level)`:

- Уровни 1–2 оставляют текущий пул смещений (±5, +30, +55 мин, ±1/2/3/6/9 ч). При времени, кратном 5, все смещения дают минуты, кратные 5, поэтому варианты остаются в шаге уровня.
- Уровень 3 сначала добирает два-три варианта в том же 24-часовом часе, что и ответ: случайные минуты от 0 до 59, отличные от минуты ответа. Остаток добирается тем же старым пулом с шагом 1 минута.
- Дедупликация по `visualKey()` сохраняется как единственный фильтр: при одинаковом часе и разных минутах коллизий нет, а пары вроде `14:20`/`02:20` по-прежнему не попадут в один набор.

Требование «минимум три варианта в одном часу» выполняется детерминированно: ответ уже в этом часу, плюс два добранных варианта. Запасной цикл (не более 50 попыток) страхует от вырожденных случаев и повторяет подход из режима 3.

### 5. Пауза 5 секунд на отдельном таймере

`cooldownUntil` — метка времени (`Date.now()`), выставляемая при каждом принятом ответе (верном или неверном): `cooldownUntil = Date.now() + 5000`. Проверка `coolingDown()` в начале `pickOption()` игнорирует клик, не меняя ни баллы, ни ошибки.

Отсчёт ведёт отдельный `setInterval` на ~250 мс — **не** через `schedule()`, потому что `schedule()` отменяет единственный общий `timer`, которым управляет переход к следующему заданию. Интервал:

- обновляет текст `#cooldown` («Можно отвечать через N с») и снимает текст по истечении;
- проставляет/снимает `disabled` у кнопок `.opt`, чтобы состояние было видно и клики не проходили.

`renderOptions()` вызывает `syncCooldown()` после вставки кнопок, иначе новое задание, выданное внутри паузы, отрисовалось бы активным. «Сброс» делает `cooldownUntil = 0` и останавливает интервал. Смена уровня паузу не снимает — это ограничение частоты ответов, а не свойство задания.

*Альтернатива:* держать задание до конца паузы и переходить через 5 с — проще, но пользователь выбрал вариант «задание раньше, варианты закрыты».

### 6. Штраф и счётчик ошибок

На неверном ответе: `state.mistakes++`; если у уровня `penaltyEvery > 0` и `state.mistakes === penaltyEvery`, то `state.score = Math.max(0, state.score - 1)`, `updateScore()`, `state.mistakes = 0` и к тексту фидбэка добавляется «−1 балл». На верном ответе `state.mistakes` уменьшается на 1, но не ниже нуля: ребёнок может «заработать обратно» накопленные ошибки. Сброс счётчика в ноль вместо `%` делает индикатор «N из M» тривиальным.

Счётчик `#mistakes` показывается только при `penaltyEvery > 0` и обновляется в `syncLevelUi()`, которая также переключает активную кнопку уровня и видимость подписей минут. Одна функция на все точки входа: старт, смена уровня, «Сброс», ответ.

### 7. Разметка панели

В `#panel1` над вопросом добавляется строка уровней (`.levels` с тремя `.lvl` и `data-level`), под вопросом — `#mistakes` и `#cooldown`. Кнопки уровня оформляются как компактные «чипы» в палитре проекта, активная получает класс `active` и `aria-pressed="true"`.

### 8. Формат вариантов на сложном уровне

`renderOptions(opts, level)` получает уровень: на третьем он вставляет единственный `<span class="t24">` и вешает на кнопку класс `solo`, который увеличивает 24-часовую запись до обычного размера варианта. На уровнях 1–2 остаются два span'а (12ч крупно, 24ч мелко). Фидбэк продолжает собираться через `pairLabel()`, поэтому сообщения на всех уровнях перечисляют оба чтения — это обучающий момент, а не подсказка в момент выбора.

*Альтернатива:* переиспользовать `.t12` для 24-часового текста — быстрее, но имя класса начинает врать, и следующая правка стилей легко ломает вид вариантов.

## Risks / Trade-offs

- [Подписи минут могут визуально тесниться с цифрами часов и кончиком минутной стрелки] → радиус 58 выбран между концом стрелки (56) и цифрами (68); размер шрифта задаётся в CSS и проверяется вручную на 380px.
- [Отдельный интервал легко «утечёт», если не остановить его при сбросе] → интервал сам останавливается по истечении паузы, а «Сброс» дополнительно вызывает остановку; `syncCooldown()` — единственное место, меняющее вид кнопок.
- [Пауза 5 с при задержке нового задания 2,3 с оставляет ~2,7 с «мёртвого» ожидания] → отсчёт прямо объясняет ожидание; при желании задержки можно сократить без изменения спек.
- [Уровень 3 с шагом 1 минута делает варианты визуально близкими, и ребёнок может ошибаться чаще] → это осознанная цена сложного уровня; штраф каждые 2 ошибки и счётчик заранее предупреждают.
- [Уже принятый ответ и нажатие «Сброс» могут пересечься по времени] → «Сброс» снимает паузу и вызывает `nextTask()`, который чистит общий `timer` и `state.locked`.
