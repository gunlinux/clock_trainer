# Design

## Context

См. `proposal.md` — Why. Обработчик вкладок в `app.js` навешивается на каждый `.tab` и при любом клике: снимает `active` со всех вкладок, ставит её выбранной, пишет `state.mode`, скрывает все `.panel`, показывает `#panelN`, вызывает `syncLevelUi()` и `nextTask()`. Именно безусловный `nextTask()` и позволяет перебирать задания повторным кликом по активной вкладке. `state.mode` — единственный источник истины о текущем режиме; видимая панель и подсветка меняются только в этом обработчике.

## Goals / Non-Goals

**Goals:**

- Повторный клик по активной вкладке не меняет ни состояние, ни DOM, ни таймеры.
- Переключение на другую вкладку сохраняет прежнее поведение: новая панель и новое задание.
- Пауза и сообщение после ответа не обходятся кликом по активной вкладке.

**Non-Goals:**

- Не запоминать задание отдельно для каждого режима: возврат на вкладку после переключения по-прежнему выдаёт новое задание.
- Не менять «Сброс», паузу, уровни и генерацию заданий.
- Не менять разметку и стили вкладок.

## Decisions

### 1. Ранний выход в начале обработчика вкладки

В начало обработчика добавляется проверка `if (+tab.dataset.mode === state.mode) return;` — до снятия `active`, до скрытия панелей и до `nextTask()`. Так клик по активной вкладке становится полным no-op: не сбрасывает `state.locked`, не очищает `timer`, не прячет сообщение и не трогает `cooldownUntil`.

*Альтернатива:* отключать `disabled` у активной вкладки — отклонено: кнопка перестала бы получать фокус, изменился бы её вид и поведение для клавиатуры, хотя визуально она и так уже выделена.

*Альтернатива:* сравнивать видимую панель по классу `show` — это второй источник истины рядом с `state.mode`; расхождение между ними как раз и создало бы баг.

### 2. Пауза не останавливается

Проверка стоит до любых вызовов, поэтому `stopCooldown()` не вызывается, и оставшиеся секунды идут как обычно. Это осознанно: клик по активной вкладке не должен быть способом снять паузу или досрочно получить задание.

### 3. Возврат на вкладку остаётся сбросом задания

После переключения `state.mode` уже другой, поэтому обратный клик проходит проверку и выдаёт новое задание. Это соответствует решению пользователя: закрывается только повторный клик по активной вкладке.

### 4. Режим 3 не требует отдельной правки

`nextTask()` для «Поставь время» не вызывается, значит `dH`/`dM`, цель и цифровое табло остаются на месте. Отдельной ветки для третьего режима не нужно.

## Risks / Trade-offs

- [Ребёнок всё ещё может сменить режим и вернуться, получив новое задание] → это осознанно оставлено пользователем; полный запрет потребовал бы хранить задание для каждого режима и менять все три обработчика.
- [Проверка сравнивает `data-mode` со `state.mode`, и при будущем программном переключении режима мимо вкладок они могут разойтись] → сейчас режим меняется только обработчиком вкладок; при появлении другого способа переключения его нужно будет обновлять вместе с `state.mode`.
- [Клик по активной вкладке во время показа сообщения выглядит «мёртвым»] → это и есть требуемое поведение; сообщение исчезнет по обычному таймеру, а не по клику.
