# Design

## Context

`renderDigital()` сейчас заполняет левую пару цифр сырыми `dH`/`dM`, а правую — из `pairLabel()`. Поэтому при `dH = 13` обе пары показывают `13:15`. Автозачёт сравнивает `dH * 60 + dM === state.answer`, то есть точные минуты суток, хотя `01:15` и `13:15` — одно положение стрелок. `visualKey(t) = t % 720` уже используется в других режимах для этого правила.

## Goals / Non-Goals

**Goals:**

- Левый индикатор всегда показывает младшее чтение, правый — двойник +12 часов.
- Засчитывать цель по положению стрелок, а не по точному 24-часовому значению.
- Не менять шаг, перетаскивание, кнопки, уровни и скрытие табло.

**Non-Goals:**

- Переводить внутреннее `dH` на диапазон 0–11 и переписывать перетаскивание часовой стрелки.
- Менять формат цели, подписи или сообщения обратной связи.

## Decisions

**Обе пары цифр из `pairLabel()`.** `renderDigital()` берёт `h24a` для `#digH/#digM` и `h24b` для `#digH2/#digM2`. `dH` остаётся 0–23: левый индикатор сам циклится 00:00–11:59, правый показывает +12, поэтому визуально режим «крутится» по 12-часовому кругу без переписывания состояния и перетаскивания.

**Автозачёт через `visualKey()`.** Условие становится `visualKey(dH * 60 + dM) === visualKey(state.answer)`. Это автоматически принимает и `11:30` для цели `23:30`, и `13:15` для цели `01:15`. Альтернатива — сравнивать левое чтение с `pairLabel(answer).h24a` — даёт тот же результат, но дублирует правило 720-минутного цикла; `visualKey()` уже является каноническим помощником.

## Risks / Trade-offs

- **Смена `dH` на 0–11 выглядит более «чистой»** → отклонена: пришлось бы менять перетаскивание часовой стрелки и половину суток; визуально левый индикатор и так циклится 00–11.
- **Две цели с одинаковым положением стрелок** → это одно задание по доменному инварианту; оба чтения и должны засчитываться.
- **Скрытое табло** → `renderDigital()` продолжает обновлять цифры, автозачёт по `visualKey()` работает и на «Средне/Сложно».
